# 动态导航已有成功案例：对 Phase 的可执行判断

2026-11-09。回答用户“怎么才能通过动态的？以前没有成功的论文与案例吗？”。本次是一手文献与仓库证据复核，模型初始化、物理积分、导航、预测积分、训练均0；已闭V920/V924及原截止不变。不启动新物理窗口，不调用Stage，不委派其他聊天/代理。research工作流按用户隔离要求在本聊天完成。

有成功论文和实机案例。现有证据支持调整整体规划—预测—执行结构，不能再靠延长同一失败配置或反复改膨胀参数期待解决；但论文中的成功不构成当前任务必然可行或某个插件即插即用的证明。

## 核对过的一手来源

| 方法 | 证据和适用边界 | 可以借鉴的机制 |
|---|---|---|
| Brito等，LMPCC，RA-L2019 | 真实Clearpath Jackal车载定位、感知、规划，与两位行人交互；另有汽车仿真。50ms采样；文中1/3秒预测时域的参数评测耗时低于50ms，5秒时域99分位超时。不能把该结论外推到本车或任意障碍。 | 联合选择轨迹与控制，按未来时刻约束预测障碍；参考线允许绕开。[作者论文](https://arxiv.org/pdf/2010.10190)、[学校正式发表信息](https://research.tudelft.nl/en/publications/model-predictive-contouring-control-for-collision-avoidance-in-un/) |
| Rastgar等，PRIEST | 原论文动态仿真30种配置、10个运动障碍，报告83%成功。多分支采样结合可行投影，GPU并行。主BARN比较是全向双积分机器人；公开动态入口另有nonholonomic/Jackal脚本，不能将其等同于本Ackermann执行器模型或实机验证。 | 在优化过程中探索不同绕行通路，避免所有候选落在同一不可行区域；部署需重新处理车身与转向滞后。[原论文](https://arxiv.org/pdf/2309.08235)、[作者实现](https://github.com/fatemeh-rastgar/PRIEST) |
| Rösmann等，TEB，IROS2017 | 有真实Lego EV3类汽车闭环实验，包含倒车、转向间隙与模型偏差；文中该实机演示是有限视野发现障碍，不能冒称密集移动行人验收。 | 同时优化时间、速度和满足汽车最小转弯半径的轨迹，说明本类底盘并非只能用纯路径跟随。[作者论文](https://rst.etit.tu-dortmund.de/storages/rst-etit/r/Global/Paper/Roesmann/2017_Roesmann_IROS.PDF) |
| Nav2 MPPI，现成工程实现 | Jazzy分支README将其描述为可偏离参考的预测控制器，支持Ackermann，给出作者测得的50+Hz CPU结果。当前文档与分支README速度表述有差别，不能用较新100+Hz数字冒充本机实测。 | 可作为无需先训练的预测控制骨架和公平基线；本机已安装1.3.13库。[官方Jazzy实现说明](https://github.com/ros-navigation/navigation2/blob/jazzy/nav2_mppi_controller/README.md) |

Nav2官方将RPP定位为精确路径跟随；其JazzyREADME明确要求上层提供可跟随路径。MPPI可在障碍阻断参考时偏离参考。[官方选型](https://docs.nav2.org/jazzy/configuration_and_development/tuning_guide/)、[RPP说明](https://github.com/ros-navigation/navigation2/blob/jazzy/nav2_regulated_pure_pursuit_controller/README.md)。这不表示RPP不能参与动态导航，而是绕障轨迹必须由上层持续生成，不能只向它提交无法执行的参考。

Nav2标准MPPI的CostCritic查询当前二维costmap；它不会仅因名字包含“预测”便自动得到障碍速度、未来占据与本项目不确定性保证。若接入按时刻的障碍预测，需要额外设计、数据来源和独立审核。[本机对应1.3.13 CostCritic](https://raw.githubusercontent.com/ros-navigation/navigation2/1.3.13/nav2_mppi_controller/src/critics/cost_critic.cpp)。

## 我们为什么没有通过：本地事实和推断分别记录

1. **已有MPPI失败记录不能抹去。** V862用SmacHybrid+MPPI、Ackermann最小半径1.32米、open_loop=True，180秒未到达；实际走16.23米，其中倒行投影6.96米。车辆确实执行了大量前后命令，唯一根因尚未证明。同模型V863换RPP后静态到达。来源：`docs/NAV2_READY_STATIC_V862_EXECUTION_REPORT.md`、`docs/NAV2_RPP_STATIC_V863_REPORT.md`。因此“立即换MPPI就能成功”没有证据。
2. **当前全局参考与执行门不一致。** V920保存的767次前进请求回退全部仅全周期终端拒绝。V924通过硬参考和同集合完整多边形距离改善，发现后走3.857657米，但剩1.797270米未到达。其后保存态781次请求回退均静态下界不足。完整V924证据审核通过不等于功能通过。来源：`docs/NAV2_NATIVE_INGRESS_V920_V924_ANALYSIS.md`、`records/nav2_v924_20261109/main_we_INDEPENDENT_AUDIT.json`。
3. **安全停车不提供持续到达机制。** 长期保留一个有效停车凭证可以避免无证运动，却不会自动产生离开该区域的控制。把每个短命令终点都限制在同一全周期可等待区域，会排除利用障碍运动时隙的方案；这是对当前机制的推断，不是本地图存在可行时序解的证明。
4. **静态余量与终点选择也冲突。** V926为覆盖最坏执行管设置.27米全局余量，旧8厘米终点候选的最大净空仅.255米，Smac在虚拟终端根205。V927使用原45厘米到达域内20厘米固定候选，终点净空升至.375米并消除205，但相同三态搜索仍208、没有合格路径。只改目标区域或统一加厚地图不足。
5. **时序故障独立存在。** V920最终ROS观测陈旧先发stop，后排队命令在STOPPING被拒；V924最终ROS心跳年龄门停止。已记录的阶段重算耗时不能确定历史锁等待、调度、GC、栅格化、序列化各自责任。应加入计时并隔离慢路径，不能直接放宽时效门。

原物理车身约束、原生.15米净空和完整状态控制重放都继续用于验收。当前算法采用公开.32rad/s周期先验以及条件经验误差；若下一方法改变全周期终端合同，必须声明新的有限时域/后备假设，不能声称保留原无限期等待能力。

## 建议采用的技术路线与可证伪顺序

**优先完成一个经过匹配的成熟预测控制基线，再把RP-CCR的风险—进展—走廊恢复放入同一轨迹评价/约束接口。** MPPI已安装、无需训练，适合首先复核；若名义模型不能表达本车转向/速度滞后，应匹配模型或评估MPCC，不能不断添加外层补丁来掩盖内层失配。PRIEST保留为后续多通路采样参考或比较，当前ROS2和汽车模型适配成本不能忽略。

- **先验证闭环一致性。** 固定转弯、制动、换向和参考方向切换输入，核对名义预测与真实执行响应；特别复核V862频繁反向的参考/控制关系。保留已有静态成功RPP作为参照。同一车身、实际速度/转向/加减速、地图与起终点；不只检查插件能加载。
- **用时间而非全周期静态并集表达移动障碍。** 在每个未来时刻评价完整车身与该时刻障碍集合的分离，让等待、减速、绕行、必要倒车成为有限动作序列。推进同时保留实际可执行的制动/退让后备；任何新准入机制先经数学/保存态/原生响应资格，不能删除门后把旧失败追认为通过。
- **静态与动态共用执行尺度。** 在轨迹搜索/优化内计算当前方向、姿态与状态对应的跟踪/制动余量；全局参考不能只在.15米裸车几何上有路，执行又要求额外误差余量。避免把最大反向残差整图永久膨胀造成新的封路。
- **目标与进展共同评价。** 在原45厘米实际到达区域中选择满足同一约束的可到达终态；预先验证完整通路/可续接序列，观察真正目标距离变化与停滞。一个停车证书或一条几何路径不能充当完整任务成功。
- **隔离快控制与慢更新。** 先以20Hz控制/100Hz执行为测量目标，收包、控制、跟踪、锁等待、规划、栅格化、持久化分别计时；有界缓存将重归档移出控制回调。50ms预算是待验证目标，不是已测保证。MPPI参考参数56×.05=2.8秒；若速度仅.1m/s，名义前视位移只有.28米，必须按转弯与障碍尺度设计时域，不能原样照抄速度更高论文的参数。

预先设置决策门：同配置完整静态跟踪→一条真实动态开发主+完整重复→同版本三路线→事前冻结未暴露确认。基线与RP-CCR版本共享模型、传感信息、物理安全验收和计算预算，算法附加约束各自明确。MPPI基线若在同一阶段失败，先查模型/参考/系统；基线过而RP-CCR版失败，直接定位新增风险/恢复机制。公平基线应在开发期就使用，而不是等RP-CCR全部通过后才第一次尝试。

当前研究判断：已有论文证明这类任务有成熟实现路径；我们尚未建立可靠的规划—动态预测—执行闭环，继续给同一RPP外层加厚约束不是最快的路线。通用导航跑通是基础工程，RAS论文仍需证明RP-CCR增量对进展、停滞、风险和时间预算的净收益，不能把换成MPPI写成新算法贡献。
