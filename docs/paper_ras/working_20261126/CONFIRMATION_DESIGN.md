# 独立确认与机制实验：登记前设计

状态：DRAFT，不是已预注册的正式任务表，不构成模型/物理准入。旧共同120项、消融20项及所有失败保持。此处不创建新once、不更换旧seed、不将已看过的结果作为新确认。

## 1. 两层研究问题

**系统层：** 冻结最终RP-CCR与事前选定的两个合格强对照，在共同可用信息、车辆、外部评价及明确计算条件下，比较完整到达、实际安全、功能拒绝和技术故障。选对照基于方法相关性和实现资格，不依据谁在旧正式结果中表现最差。

**模块层：** 相同名义控制器、相同输入和候选预算下，只改变一个可安全执行的模块。PSF/PCBF只有在Phase原车辆模型、约束、不确定性及终端条件完整资格后，才可占用对应比较位置。原数学夹具通过不替代资格。

## 2. 可先完成的任务构造设计

先在独立公开开发集合验证场景生成、车式可行参考、因果传感和通用提案；开发集合不进入确认。确认设计候选为6个独立的新布局×2组起终点×2个事前固定的actor相位，形成24任务/方法；3个系统合计72个方法任务。这是有界初步泛化研究规模，不是“达到某期刊所需样本数”或既定功效保证。

布局按事前规则覆盖转弯、窄通道和交接区域；不从导航成功结果挑选布局。actor仍先限制为已资格单actor运动类。新地图与多actor是不同研究因素；本轮设计不同时偷换两者。各方法拥有同一公开地图和传感机制，真值只用于构造/评价，因果观测随实际轨迹产生。

正式清单必须在首次算法导航前生成并锁定，包含几何文件及SHA、地图ID、起终点、actor参数、传感种子、方法版本与参数SHA、t0可行性筛选规则、完整失败/未执行处理、运行顺序、实际/重放/存储和墙钟预算。t0筛选结果及未入选理由保留，不以导航结果替换失败任务。任务ID可以先确定，但源生成器和最终方法未冻结前不伪称确认集锁定。

不同布局是主要泛化单位，同布局的起终点/相位不能当成独立地图。报告逐布局结果和配对差异；6布局下区间稳定性有限，不用普通独立二项式区间冒充跨地图可靠性。若主张高可靠性或较小效应，需要在确认结果揭盲前，基于独立先导、预设最小重要差异和聚类结构计算样本量；不能看显著性后追加到显著。

## 3. 机制实验登记字段

onward：预检是否调用、候选ID/顺序、预检结果、实际选中prefix、预测交接状态、实测交接状态、观测版本、后续规划结果、全任务结局。no_onward只移除预检，原反馈/停止/实测后续规划保持。

time：是否进入时间选择分支、全部注册候选的资格、wait0与非零wait的结果、选择结果、实际等待与执行、完整结局。未进入记inactive；日志缺失记unknown，两者不得合并。

在公开开发任务检验上述字段和合法变体；正式机制任务的激活条件与构造规则须在导航结果之前确定。原20项不补跑、不删失败。所有注册配对都报告：机制未激活、已激活但无差异、有轨迹差异但无到达差异、有到达差异、证据不完整。不可只分析有利或完整成功配对。

## 4. 主要和辅助终点

主终点：注册完整目标、完整停车及适用独立证据共同通过。技术失败保留在任务分母，并另外给出可解释性分类。安全终点：最低实际净空、坏接触/自体事件、输入合法性和完整capture/replay。辅助终点：停驶/恢复次数、发现时刻、拒绝阶段、目标进展、路径长度和仿真时长。

路径长度/到达时间只在明确的共同成功子集中作配对描述，同时展示全体失败和截尾；不能把早拒绝算法当作更快。主要结论与次要指标、多方法比较及其区间方法在清单锁定时确定。

G1：最终候选与接口只读冻结、每个对照在公开开发任务通过基本能力验证。

G2：新的真实车式模型/地图/传感/动作/安全合同、全capture/replay/审计、终止处理和预算资格通过。原安全门不下降。

G3：完整新任务登记、顺序与分析方案锁定，SOURCE恢复链就绪，旧当前轮已闭账，无重复身份且执行资源不冲突。

G4：每轮科学关闭、准确未知计数、远端逐项核验和精确清理后进入下一任务。任何新正式批的有限总窗另由具体资源预算确定；不侵占V2109正在运行的冻结窗口。
