# 用户确认的验证顺序

2026-11-07用户确认：实体车软件接口尚未接入，且明确要求“现在先在仿真里面进行，一切都跑通之后才开始实体机”。

本指令取代此前提出的“实机接口与仿真并行准备”建议。当前不连接硬件、不开发或运行电机驱动、不发实机命令，不因论文目标提前推进实体机。

固定依赖顺序：

1. 仿真车辆模型与合法速度/转向/制动资格，排除装配碰撞异常；完整状态控制重放和几何/外部接触验证。
2. 同一最终模型下真实Nav2三路线静态物理导航。
3. 同版本固定单小actor动态开发，记录真实测距发现、恢复后续行和严格到达。
4. RP-CCR在成熟Nav2骨架上同预算机制消融、强基线和独立留出确认；同时验证连续墙钟运行、观测年龄和超时交接。
5. 上述仿真链条完整通过、证据独立审核后，再讨论实体车接口、低速执行器/定位联调及实机实验，另立具体协议。

“一切跑通”不以一个解析运动学软件测试、一条路线成功或只无碰撞代替。范围是已声明的模型/场景/传感/预算合同，不意味着所有可能动态环境都已验证。失败保留，不取消门槛，不延长旧批截止；无人监管或断网长窗需要明确有界计划。
