## 三个假设的检查结果

1. **起步时差速分配被限幅挤掉：成立，但不足以解释全部失败。** 117个反馈步中7步发生投影限幅，最初6步（6114–6119）请求非零差速而实际分配为零。首步两后轮目标均为0.0875rad/s，均达到原每步变化率上界；固定这个公共值后，合法差速区间只能是[0,0]。同速率/符号约束下让一轮暂缓加速可以提供差速，代价是公共速度下降；这是代数见证，不是新物理成功。其余110个反馈步没有投影限幅，因此只修这6步不能声称解决全部航向失配。
2. **最终四执行器目标缺少统一转弯关系：有直接保存证据，应优先修正。** 45个原生步（6124–6168）的前轮目标与后轮目标，按同一无滑移滚动关系反推出相反符号的曲率。新反馈对后轮目标进行独立纠偏，前轮仍从另一项原Twist生成；逐轮幅值/速率合法，并不能证明四个目标对应同一条车辆转弯运动。后轮目标所隐含的滚动曲率最大2.366/m，这不是实测车辆曲率，也不能将其当成实际物理安全违规。其后51步（6180–6230）实测前轮已经正转向，实测车体偏航仍显著为负。这些观测不能唯一分辨接触滑移、伺服负载和惯性，但已足够说明“加一个独立后轮偏航反馈就能跟踪”的假设没有得到验证。
3. **主要只是停车尾造成：不成立。** 原在线包航向误差0.0349344，加原离散保留量已经越门；第一停车输入前误差进一步达到约0.0351365。停车尾峰值增加约0.00604弧度。应同时处理行驶误差和停车余量，不能删尾、缩短统计区间或提高0.035门掩盖问题。

还必须保留反证：V982在加入这项独立后轮偏航反馈之前，也已发生航向超限。因此不能把新发现的目标分配不协调说成所有旧失败的唯一根因，也不能把回滚为原V958称作修复。真正需要验证的是协调后的执行动态能否支持原参考，而不仅是让指令公式变得一致。

V989用于逐步图解的曲线由原在线解析参考重建；其全尾航向峰值0.041173016，与另一份独立中点重建0.041172377相差约6.4e-7。原独立审核结论及其保留量不被替换。

## 下一步做什么

下一候选先完成**一个协调的车辆控制分配层**，不再只增加后轮偏航增益。正常RPP仍给期望运动；允许的跟踪反馈只能改变一个共同的虚拟转向/曲率请求，前轮目标和后轮差速均从它生成。纵向PI改变公共轮速时，后轮差速也应保持同一转弯关系。所有幅值、变化率和前进约束在联合分配中同时满足；必要时降低可实现的公共速度，而不是先把两轮推到限幅，再追加独立差速。

这只是一项前瞻设计，不是证明“统一后必然成功”。对于轴距L=.60、轮距B=.54的既有运动学约定，目标应满足：

```
tan(delta_left)  = L*kappa / (1 - B*kappa/2)
tan(delta_right) = L*kappa / (1 + B*kappa/2)
omega_left      = mean_omega * (1 - B*kappa/2)
omega_right     = mean_omega * (1 + B*kappa/2)
```

上式只是执行器目标的滚动一致性约束，不是实际接触动力学模型。先核对模型坐标/关节符号与当前车体参考点，继续对**原车体参考点与原固定路径**审核；不能悄悄换到更好看的参考点。真实转向滞后、轮速负载和停车偏航仍须实测，不能用这些公式取代物理资格。原V977参考保持时，若车辆动态响应仍无法满足原跟踪包络，应明确拒绝该候选、补充执行动力学和停车余量建模，而不是宣称该恢复走廊可执行。

完整准备顺序及拟议物理范围见[下一实验设计](../experiments/v989_actuation_reference_diagnosis/NEXT_EXPERIMENT.md)：先对真实保存输入完成协调分配的红例与零模型资格，再申请原两个保存态组件，首项成功才第二项。两项都通过完整跟踪、停车尾和重放门后，再另行安排西向东整路；本次不启动模型，不自动整路、三路线或24项。
