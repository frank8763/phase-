# 实验加速约定

用户2026-11-17明确要求“以后的实验都要加速”，并允许充分利用CPU/GPU。

- 独立解析候选默认使用已验证的四个低优先级CPU工作进程，固定候选顺序选择，保留准确计算账目；进程隔离原C++全局计数器。优先缓存不可变域几何、复用已通过的科学资格与已完成实际主任务，避免为了操作修复重复跑车辆。
- 真车辆模型、MuJoCo导航与原生自身重放维持现有单实例Phase执行锁和完整安全/控制/重放门。只有事前验证决策和全状态等价的新并行实现才改变这一约束。
- GPU仅用于具有可验证实现且预计能减少总墙钟时间的计算，不把设置CUDA_VISIBLE_DEVICES冒称GPU加速。当前四核解析搜索是已运行的实现，无GPU加速声明。
- 资格围绕实际调用口、真实保存失败输入和独立核验。只重做受影响检查；日志/输出接口修复优先核验原完整证据，不重跑已成功主任务。全审CLI输出已规范化JSON文件，并检查真实命令退出码，避免摘要序列化错误中断任务。
- 有限接力在前一批全门通过、封档回读和锁空闲后自动执行，失败则封账；不借加速取消截止、降低门槛、混分母或刷种子。
- 后台自主运行，用户主动检查时读取紧凑状态，不为健康进度持续消耗对话额度。
- Stage完全隔离：不访问其源、模型、结果、进程或资源清单；现有CPU预算使用低优先级，不通过观察Stage分配资源。未来扩大并行预算需测量本Phase收益，不能凭核心数宣称提速。
