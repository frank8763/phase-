# V892失败原因与V894待验修订

V892仍未通过：实际77.20秒/7720原生及7720自身完整重放，误差0，最低实际净空0.269035345m/坏接触0。发现后8次成功周期参考、实际续行0.926040m，末距目标3.523539m/末速7.38e-6m/s，ROS最终208。条件完整重复未启动，原窗口按首失败关闭；不是新24确认失败率。

现在有两类直接证据，不能只归因为控制器跟踪：

- 原32束11.25度间距对小actor持续观测不足，实际最长可靠未知回波断档8.05秒；因果位置集合必须扩张，无回波不能擦掉障碍。这部分约束没有通过降低安全门或引用真值消除。
- 新增31份完整全局主图中，3份所有1000000格均255未知；同时原BT反复请求ClearEntireCostmap。原allow_unknown=false，未知不可当作自由。官方[清图源码](https://raw.githubusercontent.com/ros-navigation/navigation2/1.3.13/nav2_costmap_2d/src/clear_costmap_service.cpp)确实调用resetLayers，不能把服务返回解释成下一次规划已经拿到更新完毕的地图。[RecoveryNode源码](https://raw.githubusercontent.com/ros-navigation/navigation2/1.3.13/nav2_behavior_tree/plugins/control/recovery_node.cpp)也表明恢复成功会计入重试数，RUNNING本身不会重置该计数。

V893只做零车辆软件验证，固定原60.31/62.91/72.01三实际保存扫描/位置集合，运行真实安装Nav2。明确清图后可复现100万未知；等待1.2秒不重清，已知静态恢复。前两状态稳定地图返回205和212点完整路径，第三状态仍208，不能把等待说成必然存在通路。首次只等固定时间的资格仍观察到229460未知，原FAIL保留；实际双GetCostmap门通过。该行为受更新线程竞态影响，不要求每次GetCostmap都能抢在地图恢复前读到全未知，也不据此断言整次失败只有一个原因。

V894候选源码已准备并冻结，尚无物理授权或模型窗口：

1. 取消原BT所有整图清空，改为1秒等待；地图及动态占据保留，原不可恢复错误条件保持。
2. 使恢复预算覆盖原180秒导航：恢复上限180来自每次至少1秒等待，导航180秒和240秒外层期限均不延长。
3. ARM前检查两份真实全局主图，相隔至少.55秒；原尺寸/坐标/.01分辨率，未知0，且原PGM全部72683静态占据格都保持lethal254。全自由伪图也拒绝。完成后重取生命周期ACTIVE证据，再启动原生积分。

保留V892全部模型、传感、actor、控制、目标和安全门，不修改原32束传感配置。16真实入口/33依赖检查和8地图契约用例已过；真实GetCostmap验证了相同主图门。资格是软件与保存输入检查，不是实际动态到达，也没有执行新NavigateToPose或车辆控制。
