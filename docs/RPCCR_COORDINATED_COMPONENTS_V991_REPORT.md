## 用户追问：为什么旧24项已成功6项，新版还回查组件

这是结果退步，不只是统计口径要求变严。原V826算法/V827三路线开发及三完整重复通过；V828原24项执行前8个西向东，其中6完整成功、10060002缺新恢复命令/10060008墙钟截止未到达，余16及三固定确认重复未执行。原任务保留，不能把6成功说成0成功或把未执行说成失败。

原确认至少23/24、每路线7/8；已有2次失败，即使余16全过最多22/24，且西向东只能6/8，所以该已闭批不能只补剩余16项来取得通过。改算法后也不能将旧6项成功挪入新候选分母。

后续为解决计算成本，名义导航/控制、预测方式、安全合同和恢复监督发生实质替换；旧V828八任务含37224712私有原生预测，当前Nav2分支私有积分0，但省掉计算没有自动保住恢复与持续进展。旧完整328步原生预测合同，与当前命令管/制动尾/周期终端及经验执行界不同，不能声称只做了等价加速、所有旧保证不变。当前结果尚未恢复到旧版六项完整成功与三路线开发水平。

流程问题是切换架构后没有先锁住同版本整路能力，连续局部修补又带来新回归。现在V991仅两个已保存失败状态验证新V990控制，避免每次用整条导航诊断一秒内的跟踪故障；不再重复原18响应、不开新候选池或调增益。两状态全门通过后进入同版本整路主/完整重复，再做另两路线并进入新的冻结确认。旧成功作为历史锚点保留，不重写成当前成功，也不重开旧窗口。
