# 下一轮：分离离线辨识与在线时序，恢复可执行走廊

## 为什么下一项应这样改

V991已在原生最大lag约3.76ms、实际控制协调成立的条件下，出现完整停车尾航向误差.041595rad>原.035rad，说明实际跟踪问题不能全部归为主机慢或指令映射没接上。V993则在第二项新301步后被墙钟lag门终止，它没有完整停车尾和重放，不能作为已完成的转向响应实验。

V993没有ROS控制器反馈，其刺激由原生步索引、固定任务和原初始曲率确定；控制器dt=.01，actor和测距由仿真时间/原生计数推进。当前源码中BODY_COMMANDS使用monotonic只作事后时间记录。仍需检查被包装依赖和实测等价，不能仅据这些源码就宣称完全与墙钟无关。

MuJoCo官方Python例程将mj_step与用于贴近墙钟的sleep分开；物理数值积分按模型timestep推进。这支持把固定输入离线辨识和实时闭环性能分开评价，但本仓库的依赖独立性必须另验。[MuJoCo Python](https://mujoco.readthedocs.io/en/latest/python.html)、[MuJoCo计算流程](https://mujoco.readthedocs.io/en/stable/computation/index.html)。

MuJoCo位置/速度伺服最终产生参与动力学的执行器力，不是直接令车体实现目标运动；ros2_control的转向控制库也明确其逆运动学更新不实现路径跟踪反馈。因此“四轮目标协调”只是必要的一层，不能代替实际伺服与车体响应资格。这是下一实验的工程判断，不是已证明某一种机械因果。[MuJoCo执行器模型](https://mujoco.readthedocs.io/en/stable/computation/index.html#actuation-model)、[ros2_control Jazzy](https://control.ros.org/jazzy/doc/ros2_controllers/steering_controllers_library/doc/userdoc.html)。本方案不安装或切换该控制库。

先运行同一6083保存态的原保持转角任务：全部800新步、200步停车、原历史和自身全轨迹重放；与V993完整保持转角的qpos/qvel/ctrl/mocap误差<=1e-8、规范模型/初态、接触及发现一致。它的目的为新执行方式的等价桥接，不是重新争取一个旧成功，也不计新导航样本。若不能精确等价，停止辨识依赖，查明隐藏墙钟输入或执行差异。

## 2. 分解误差，只提出一个候选，拟最多25分钟

每项分别计算：

- 目标转角对应的运动学偏航率；
- 实测左右转角反推的运动学偏航率；
- 实际姿态增量得到的偏航率，并核对原日志角速度、坐标轴与参考点。

第一、二项之差定位目标到实测转向的伺服滞后；第二、三项之差描述实测转向到车体运动的剩余失配。使用同一原车体参考点，不能换参考点来让旧失败变小。分别统计转向中、转角保持段和全部停车尾的峰值与积分误差；不能只看相关系数或删去停车尾。

判断规则：若慢转向仅降低瞬时峰值，而稳定后和完整停车尾的累计航向偏差仍近似相同，则“单纯降低转向速率即可修复”不被支持。若主要是目标角到实测角滞后，则候选重点为实际转角收敛与推进速度的协调；若实测转角已跟上、车体仍有系统瞬态，则候选重点为包含实测偏航率和执行滞后的恢复参考。两条为事前机制选择，最多实现其中一个有证据支持的版本，不作为两个并行候选反复试到通过。

辨识不能证明唯一轮胎/惯性/接触参数因果。参数和决策只用诊断集确定，候选在任何新执行前冻结；原第二保存态7814用于不重新拟合的检验。若证据不足以确定候选，本轮停在诊断结论，不盲加反馈增益。
