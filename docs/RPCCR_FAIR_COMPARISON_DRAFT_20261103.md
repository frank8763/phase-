# RP-CCR公平比较：设计草案，尚未实现或启动

截至2026-11-03晚，完整场地开发V790仍NOT_PASSED。今晚只整理该设计及数据接口，不移植、安装、调参或运行任何对比算法，不新增MuJoCo导航/预测/重放。不能称“明天只差写论文”。先解决完整场地持续通行、冻结算法及独立确认，才能开始比较。

## 要回答的论文问题

同样的观测、车辆、物理约束、风险先验和计算资源下，RP-CCR的风险—进展约束连续恢复，是否提高**完整任务到达**并减少倒退、换向、停滞和反复规划？是否仅靠更多计算、更强运动先验或不同传感/模型才改善？安全与到达、计算与效果分开报告。三条路线属于同一地图，不能包装成三地图泛化。

Nav2官方MPPI采用扰动采样、模型前向预测与代价加权更新，支持Ackermann模型；其Ackermann约束限制角速度与纵速/转弯半径的关系。但本车前轮转角加左右后轮独立控制有滑移，不能把Nav2的速度命令或无侧滑预测当作本车真实执行模型，也不能直接套官网频率当本项目实时性结果。[Nav2官方实现与说明](https://github.com/ros-navigation/navigation2/blob/main/nav2_mppi_controller/README.md)、[官方Ackermann模型代码](https://api.nav2.org/nav2-rolling/html/motion__models_8hpp_source.html)。

## 两类比较不能混淆

**机制比较**：所有提案器使用相同传感/因果风险构造与原严格安全接纳器，比较提案和恢复调度的增量；基线命名必须带“+common admission”，记录被拦截的命令、接纳率、后备与计算开销。这不能声称击败未经改动的Nav2完整系统。

**端到端比较**：各方法保留其原规划/风险/恢复设计，仅共享场景、原始传感、车辆执行器适配和外部评价器。若使用额外共同安全盾，必须同时报告盾的作用，不能把盾的收益全归于方法。当前协议不授权此类实验。

## 预先冻结与信息防火墙

- 开发任务、冻结确认和比较测试池分开。未来比较使用全新成对任务，种子/相位/顺序在任何方法测试前一次锁定；今晚不生成或试跑新比较池。原10030001–24仍为未执行的验收预留，不自动挪用。
- 相同已知19实体地图/三路线/完整碰撞几何、相同小actor运动类、3m传感/测距噪声/5%漏检、初态/启动3m排除先验。若改传感密度、已知速度或遮挡条件，另列实验条件，所有方法相同，不能混成算法增益。
- 比较的是同一随机任务定义，不强求分叉后收到相同测距包：车辆轨迹不同，正确做法是同源确定性噪声模型/任务种子与各自真实因果包。共同前缀若状态相同则原始包应精确一致；分叉后不能回放另一方法的传感流当实际观测。
- 在线输入只有原始包、公开车辆状态/目标、已知地图和事前声明先验；真实actor坐标、相位、未来和后验成功标签只进外部评价器。过去开发失败不能在线查表。网络/训练数据/监督更新如有区别单列；当前夜间训练0。
- 速度或曲率命令到本车4维合法执行器的适配器须独立验证，所有方法使用同一限制与速率。必须用实际MuJoCo完整状态检验；本晚不运行这种校准。

## 公平预算与报告

同时报告两种资源视角：同外层墙钟/同CPU下的任务效果，以及明确上限的原生预测工作量。相同“候选数量”不代表相同工作量，采样、优化迭代、几何域、路线搜索、BC推断、后备构造和控制重放须分项。实际公开步与预测/校验原生步分账；共同前缀等计算不等于分叉后的等总计算。

在每任务同一1200公开、780soft/900hard墙钟和原安全门下，预先指定具体预测/搜索/优化工作预算及终止规则；此处只列既有门槛，尚未冻结新的比较工作量，不能启动。随机MPPI采样种子固定；不能因某方法失败给它或另一个方法额外调参或更大池。

原逐原生净空>=.15、接触/穿透/未知0、完整自体/合法ctrl及速率、无积分外根改写、全状态重放<=1e-8与因果/覆盖/模型/源码审核不降。首次安全、源码、模型、状态、真值泄漏或证据异常按当前要求停整批，剩余任务明确未执行，不能把截尾结果报完整池成功率。若今后拟将基线的算法性碰撞改为只中止该任务，须在新协议中事前明确并经用户审阅；本草案不授权带碰撞继续凑分母。

主指标：完整发现—停稳—新路线—续行—目标到达；逐任务配对胜/负/平及未执行。副指标：最低净空、累计路径/最终净进展、倒行距离、gear切换、恢复次数、停止/停滞时间、重规划次数、实际控制时延及全部计算分账。均报告全分布和最坏值，不能只展示最好视频。统计区间与配对检验在测试前选定；一个地图的小池不支持任意场景或统计显著全面优势。

## 接口草案

`observe(public_packet, public_state, public_prior, remaining_budget) -> proposal`：不接收评估器对象、actor真值或输出目录中的旧答案。

`proposal`至少含合法目标4维执行器命令、可选预测轨迹、算法状态标识、提案时间戳、使用预算；执行器适配和外部安全评价分层记录。共同接纳实验还须输出原始提案、被过滤原因和实际提交命令，不能只保存经过安全盾美化的轨迹。

`evaluate(saved_raw_evidence)`只读核验，不生成新成功轨迹；结果保存`SUCCESS`、`FUNCTIONAL_FAILURE`、`SAFETY_ABORT`、`EVIDENCE_ABORT`、`UNEXECUTED`以及精确/未知工作量。全状态重复、源码/任务冻结、全来源与解压SHA回读沿用。接口目前是文档草案，没有运行适配器。
