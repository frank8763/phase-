# Phase记录存储规则

2026-11-07用户要求：只上传需要的，其余垃圾删除；GitHub作为长期记录库，避免占用本机磁盘。本规则替代旧批次“永久保留全部本地原件”的存储约定，旧实验失败及科学结论保持。

- Git保留源码、报告、汇总、授权、任务表、审核结论、恢复索引及运行必需的小模型。
- 同仓库Release保存静态验收、已通过三路线里程碑、最新开发完整实际轨迹和末失败见证及选定复现输入。旧失败确认保留实际轨迹/传感/已接受控制合同及账本；未选中候选池可以删除，不能再声称该精简档案能重跑全部旧候选审核。
- 重复压缩归档、重复资格视图、已淘汰候选的私有预测池及可重建调试缓存不作为永久记录，按清理清单删除。
- 必需记录须在远端上传成功、大小和SHA256相同，并完成流式下载回读后，才清除本地原始文件。上传/校验失败的必需记录继续保留并明确报告。
- 实验前明确保留项及临时磁盘预算；采用增量存档。结束上传核验后清理原始缓存。旧记录通过Release索引按需恢复，不默认下载全历史。
- 本地常驻内容限源码、摘要、运行模型和存储工具；Git采用浅历史与按需对象获取，避免旧大归档继续留在本地.git。
- 任何删除仅限本仓库内清单路径，不跟随外部符号链接，Stage完全隔离。运行中的实验目录保持完整。删除前确认Phase执行锁空闲。

上传和清理均为零模型操作；不会启动新导航、预测、训练或实体机任务。
