# 用户绿线与全局控制机制核对

用户要求车辆沿图示通路持续前行，通过中央开口并到达右侧目标。手绘是通行方向意图，不是精确的整车曲率/动态安全证书；真实动态位置不进入线上控制。

保存的4次全局路径均GLOBAL_GOAL_PATH、所有节点gear=+1、倒车节点0，均通过中央开口；原路线与用户绿线的右侧具体形状不同，不能说逐点相同。原初始路线x≈0时y≈-.801m，所选静态通路明确存在。

实际倒车出自第98、153步控制器安全回退：当时25/25普通候选均TIME_CLEARANCE，遂执行前一步已经冻结的REVERSE_BRAKE尾；不是全局路径要求倒车。原保留后备评分还含反向位移奖励。直接照着绿线强制前进会绕开当前未知域安全门，不能当作算法已解决；同样不能只删除倒车然后在无新证书时随意停车。

后续实现应保持朝全局目标的前进通行意图，将退让前的风险预警、可认证减速/观察及恢复前进联合选择；以有符号路径进度和后续可续证性考核，避免只以局部净空选择深倒车。可控前进将失证时提前选择新的完整安全合同，而不是等25个候选全拒后才执行深倒车。必要的短退让仍须完整物理证书，之后有明确的回归前进条件。具体绕动态障碍的路径由实时因果观测确定。

这是一项零模型/零积分的保存证据核对，未改控制器、未新导航，不能称已按绿线跑通。后续仍需完整场地从起点至目标的冻结开发、完整发现/制动/重规划/续行/到达和原全部安全/状态重放审核；旧失败不改。
