# 动态未到达：算法还是场景？V676原因分解

2026-11-01。用户要求全球原文检索、原因判断并继续实验。本轮尚在运行，以下先区分已查实与待验证；不把“搜索许多文献”说成穷尽所有论文。

## 目前证据更支持什么

1. 已查实的实现缺陷：原命令缓存可超过执行器硬范围，实际ctrl写入被裁剪，状态匹配却因MuJoCo内部裁剪仍为0误差。原V674/V675各10步原始命令契约不同。原失败保留；没有证据表明这种缺陷一定是全部未到达的唯一原因。
2. 已查实的选择缺陷：原217状态最高分普通安全输入无后备，次高分有原328tick后备；V675修复局部漏选仍未到达。因此不能只靠该项解释全局冻结。
3. 几何场景并非已证明封死：障碍直径0.20m，运动幅度0.25m，扫掠域距保护路口0.611419m；场景构造另有全车身绕过整个0.35m扫掠圆的几何路径证书。多数重规划也找到全局几何路线。但没有实际原生动力学到达，就不能据此宣布完整场景一定容易或动态因果可解。
4. 尚未查实：未来占据不确定性过大、空间路线/档段与真实执行器动力学脱节、短候选时域/库覆盖不足，各自对停滞贡献多少。重复同一个失败例不提供独立总体统计。

## 本轮实验顺序

先V676统一执行器硬范围/速率映射，last_command保存实际合法值，首步和整尾使用同一序列构造；每原生核对实际ctrl，公开末同时对齐完整qpos/qvel/ctrl。锁定272/294两真实旧状态作私有240tick完整重放及初态328tick证书执行，全部误差0，首失败因验证克隆漏ctrl而停止2176重放/896私有积分，修复后4672重放/12528私有PASS；全部失败原样记账。之后冻结同95000011因果导航，障碍、传感、搜索/评分/时域/门槛不变。

若因果导航未到达且完整安全/命令审计通过，再执行最多一项另列ORACLE_SCENE_WITNESS：同真实动态模型与初态，但给规划完整扫掠占据域，不把它混成未知算法。若到达，可排除“这个物理场景根本没有安全可执行路线”的强说法，但仍不能证明有噪声有限传感的原问题总可解；若也失败，仅说明这套规划控制仍不行，不证明场景无解。若因果版本身异常，立即停止依赖诊断，不继续刷实验。

新7200秒窗口最多2因果候选/1特权诊断/4总导航含成功重复，旧窗口全闭且不改。后续候选必须依据新失败，不能自动追加修订或降低门槛。动态确认、新场景、训练、实机与Stage0。

阅读补充：Zhou等v2在IV.1假设障碍状态可测/估并可恢复前步控制；其讨论明确在非线性预测失配例中未来占据不完全覆盖实际轨迹样本，因此不能借该“robust”标题声称无条件安全。Phase仍保持既定有界运动类与有限真值覆盖审计，不以意图学习暗中缩小合法加速度集合。

## 关键新增实证：同物理场景的到达见证

V677已完成474公开/3792原生严格到达，完整原生命令、状态、安全与源码独立审计PASS；这证明同模型、同初态和真实动态运动存在一条带全扫掠信息的安全可执行路径。它排除了“物理场景根本封死”的说法。V676仍是因果失败，不能将特权到达混入未知动态算法成功；两者差异同时涉及占据信息/不确定性表示及其空间引导，不能仅凭此对照把效应全部归给某一因素。
