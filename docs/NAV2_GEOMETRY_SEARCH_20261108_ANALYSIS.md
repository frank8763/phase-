# 2026-11-08：全局参考、局部圆弧与足迹栅格的一致性

目前仍未通过同版本三静态路线，未进入本轮动态。V867南北静态真实到达40.06s，说明每回合数十分钟的旧串行私有预测计算已不再是这段Nav2骨架的主障碍。西东实际没有行驶命令；它与旧V864已行驶后RPP碰撞拒绝是两个不同故障。

## 已测量的故障链

1. V867全局每轴外扩.20使WE精确目标/EW起点几何重叠.025000107m；外扩.15时同点尚有.024999893m几何余量，但5cm保守栅格判lethal。原起终点与物理场景均未改，原.15实际距离门未减。不能简单用更大矩形余量修NS而忽略端点可行性。
2. V868固定真实保存WE t0里程计/测距A/B，只把global inflation_radius.85→.90；两者action6/error208，0参考/0控制执行。此反事实否定“仅修外接圆优化范围就足够”。
3. V869同一已知几何保守栅格细化2.5cm、恢复global/local.15，固定软件WE/NS/EW/旧NS末态，另一个NS末态关闭平滑对照。三起终点足迹栅格均合法；WE实际ROS返回error207，日志“exceeded maximum iterations”（100000次）。早先把它口述为超过.5秒预算过强：它是迭代上限失败，未单独证明墙钟预算被耗尽。NS/EW/两NS末态返回首路径；EW加密参考14个lethal样本，整体资格仍FAIL。
4. V870把静态净空较小端作为Smac搜索起点，必要时两端航向加pi、结果顺序/航向还原，保留原起终点任务。1cm格仍保守包含原障碍；原10m Reeds-Shepp启发式表变大，35s生命周期预计算超时，未进入路径阶段。此原始软件失败保持。源审阅另发现必须把原搜索方向的plan话题与还原后的plan分开，进入下一软件版前修正，不冒称曾是实际导航错误。
5. V871限定启发式缓存2m（与旧10m/.05的格数相同），分离搜索plan并只发布审核后的原方向路径。四固定真实ROS软件首参考返回；WE反向查询.172107s/含还原与独立几何检查.209249s，NS.067120/.085302s，EW.173570/.193606s。WE已知整车连续插值下界.153545526m≥.15，说明可返回路径不需增加原.5秒预算。然而局部.15矩形足迹加密栅格仍拒绝WE/EW部分样本，旧NS末态理想圆弧亦拒绝，整体FAIL。
6. V872只加一格global padding.15→.16，局部.15不变；WE同一类参考/圆弧冲突仍在。仅WE和已并行进行的NS两个软件资格调用，另外两项未执行，整体FAIL。
7. V873只把V872的Smac smooth_path改false。WE查询.159845s/整代理.197736s；参考路径全整车已知几何最低.174070734m、连续插值保守下界.166180125m，局部足迹加密参考lethal0；但理想RPP圆弧lethal15，最差外扩矩形分离−.000337866m（距原目标.6925m，尚非到达区域），不满足事前资格，余三软件项停止。此为保守理想圆弧筛查，**不是新车辆实际碰撞、真实控制器必然失败或物理不可行证明**。筛查使用.08/.20固定速度、理想沿参考姿态和静态PGM，未精确复现在线膨胀层/速度调节/实际路径误差。

软件初始三路线使用公开已知地图的明确标注解析32射线夹具（没有新车辆模型），旧NS末态使用真实保存里程计/测距。V867 t0保存模型/初态但没有单独保存初测距，不能将解析夹具包装为真实MJB/测距资格；下一物理入口应保存并资格真实初测距快照。所有软件生成的cmd_vel均丢弃，V867闭批后新增模型/积分/控制执行0。

## 可保留的工程改进

通用搜索方向适配和已知静态整车连续路径审核已实现，具体代码experiments/v871_search_direction_qualification/planner_proxy.py；它未绑定路线ID/预录路径，也未读取未来actor。反向查询基于本规划包络的pi对称性，并非MuJoCo正倒车动力学等价证明。它目前只证明固定软件输入下的有界搜索，不是已资格导航器。

地图细化修复端点离散误判；固定更小启发式缓存控制启动计算；不能据此声称算法新颖或公平计算全面占优。源码中所有未合格版本和35s超时保留。一次离线审核因每个足迹样本重复转换百万格Python列表而慢，明确停止该审核进程，等价NumPy视图版本已完成；不涉及物理循环或被隐瞒的导航重跑。

## 下一步的最小修订，尚未运行

应在原Nav2框架内统一**真实控制曲率所走圆弧**与全局参考准入，避免只审核路径中心或把footprint_padding持续增大。新的参考整形/局部控制候选需要：原WE/NS/EW端点合法；原V864保存失败状态能给出通过同一局部碰撞器的前进命令；全路径包含转弯和接近目标阶段；原.15原生安全/全控制重放与数据新鲜度门保留。原RPP速度调节、临近目标减速以及碰撞圆弧应在真实软件中共同验证，不能仅以固定.2m/s理想圆弧筛查阴性证明必然停住。

先补独立零模型资格；候选未合格前不消耗真实导航。只有这组门通过、明确新的物理候选授权且仍在原物理绝对截止内，才运行同版本三静态主/条件重复，再依赖动态。原失败批绝不重开；不承诺下一版必过，不调低安全线、不换到容易任务、不把旧WE+新NS拼成三路线PASS。没有新24、训练或实机授权。

## 原始依据与论文边界

Nav2 1.3.13的Smac平滑更新只用当前位置中心cell成本检查，不能从这个函数单独推出整车曲线安全：[smoother.cpp](https://github.com/ros-navigation/navigation2/blob/1.3.13/nav2_smac_planner/src/smoother.cpp#L141)。Smac错误207在该版由超过最大迭代对应分支返回：[smac_planner_hybrid.cpp](https://github.com/ros-navigation/navigation2/blob/1.3.13/nav2_smac_planner/src/smac_planner_hybrid.cpp#L433)。RPP根据carrot曲率和经调节的线速度构造命令，再调用碰撞检查器：[regulated_pure_pursuit_controller.cpp](https://github.com/ros-navigation/navigation2/blob/1.3.13/nav2_regulated_pure_pursuit_controller/src/regulated_pure_pursuit_controller.cpp#L211)。本例平滑后参考冲突减少/未平滑理想圆弧仍冲突属于当前保存试验观测，不能由源码引申为所有任务一般结论。

RAS论文仍缺最终同版本静态稳定门、完整动态独立确认、公平MPPI/PRIEST等基线、RP-CCR新增模块净收益/消融、真实延迟测量与实体机接口/验证。成熟骨架是工程基础，不是创新本身。当前证据可作工程诊断和开发记录，不能作完整动态或统计优势结论。
