## 2. 为什么过去反复改，仍然卡住

### 2.1 三个不同问题长期被串成同一个“跟不上”

1. **参考不可执行。** V1103官方Smac迅速给出几何路径，但 V1106确认该路径约1.32 m的曲率尺度与原经验模型约1.675 m的稳态车体尺度不匹配。V1107对齐参考点和足迹后，首倒车段可完整跟踪停车。不能继续只调lookahead解决模型/参考不一致。
2. **混合模式不连续。** 原分段控制在停车换挡时，轮角、车身姿态与分配器历史并未随“路径段结束”自动归零。V1108显示名义零后驱调轮仍改变模型车身yaw，单段各自成功不能保证组合成功。需要把停车、调轮、前进/倒车及控制历史一起纳入模型。
3. **到达与安全被软代价折中。** V1109已能完整预测到达，却净空/偏差违规；V1110增加惩罚仍违规。V1111使用显式不等式并经原门独立回核才通过。继续加位置权重不能替代安全约束。

上述是本仓已观察证据，不是所有未来失败的统一归因；详见[前次复盘](RPCCR_THREE_ROUTE_CAUSE_AND_LITERATURE_20261113.md)及V1106–V1111原完成记录。

### 2.2 现在最大的风险：在同一个模型中“自证”

V1111三段零后驱调轮，经验预测分别产生约−0.07995、+0.07831、−0.08019 rad车身yaw变化，平移约0.47–0.48 mm。这不证明真实车一定不会如此运动；轮胎接触/转向机构可能引起微动。**但本轮没有物理观测验证其幅度和符号，不能把经验模型在该模式的外推当成事实。**

优化器会利用允许的模型响应。C++/Python误差接近机器精度，只能排除两种实现相互不一致；不能排除两者共同采用错误物理响应。若实际停轮调轮少转4.6°，后续整段厘米级跟踪与仅约15.2 mm的预测raw裕度就可能失效。15.2 mm只是当前raw门以上的名义余量，不能据此反推出可接受物理模型误差；误差如何进入已有不确定性预算必须独立核算，避免漏计或重复计入。

只读追溯还定位了这项响应的来源：`v1067/kernel.py` → `v1046/whole_input.py` → `v1044/whole_input.py` → `v1044/model.py`，零速度分支委托`v1003/predictor.py`。其中

`Δyaw = a × v_mid × tan(δ_mid)/0.6 × dt + b × (δ_next − δ)`，`b = −0.09385557773873891`。

因此在零驱动、残余速度消失时，调轮累积yaw近似为`b × (δ_end − δ_start)`；从−cap到+cap、cap=0.4272213734，模型会给约−0.08019 rad。这与V1111第三调轮段的预测数值吻合。这里定位的是**模型中的直接机制**，不是证明系数物理上错误。V1044的实际新增资格为前进0.08 m/s的直/左/右短响应；V1108协议也明确新停轮模式需独立物理响应资格。不能用此前移动模式资格替代该模式校准。

来源：[原预测器](../experiments/v1003_causal_recovery_execution/predictor.py)、[V1044参数](../experiments/v1044_curvature_speed_prediction/PARAMETERS.json)、[其新增实际任务](../experiments/v1044_curvature_speed_prediction/TASKS.json)、[停轮模式协议](../experiments/v1108_parked_steering_handoff/PROTOCOL.md)。本次未导入预测器、未重新积分；只读源和已保存数值。

### 2.3 慢同时来自求解结构与任务设计

本例176.01秒名义恢复中，移动79.01秒、显式调轮9秒、四段完整停车88秒。即使CPU瞬时完成求解，这条固定模式序列仍不快。它证明有限可行性，不是最佳路线或最低换挡数。

38.94秒求解加审核也不能直接作为在线反馈频率。让车等待整条长源重算，或把仿真暂停时间隐去，会掩盖真实延迟。当前125步间隔停车检查是软件资格的固定覆盖，不能冒称已满足更密的在线刷新合同。

需要分开记录：路径提案、优化、在线证书、控制分配、记录I/O、离线审计；并同时报告仿真时间、墙钟时间、实际运动/停车时间。此处没有推出某一项是全部历史耗时的唯一主因。

## 4. 推荐固定下来的架构

```text
真实传感/估计 + 控制器记忆 + 模式/时间戳
                      │
             同一混合车辆模型
                      │
   几何/拓扑引导 → 短时域约束轨迹与控制提案
                      │
       RP-CCR原因果管束认证 + 当前状态后备
                      │
          唯一分配器 → 唯一执行所有者
                      │
                  新测量反馈
```

### 4.1 一个状态定义，一个执行所有者

最低状态合同包括车身位姿、纵横速度、yaw rate、实际转向、上一实际ctrl/速率限制记忆、前进/倒车/刹停/调轮模式、测量时间与证书时间。具体维数须由实际执行器和可观测性决定，不能只把(x,y,yaw)塞给新求解器。

预测、后备、控制应用和日志均消费同一份实际分配结果。普通请求与调轮请求都必须有显式模式；不能只存零Twist后猜测前轮当时做了什么。新参考的接受是原子事务：证书未完成前旧后备不销毁；拒绝不得改变控制器历史。

### 4.2 短时域反馈，完整安全后备

保留V1111为离线完整源参照/热启动。在线只求解一个有界时域，使用实际测量初态修正；可用多重射击、灵敏度传播和RTI，避免每个变量扰动都完整滚动176秒。时域长度和控制周期先由模型误差、停稳距离、传感/计算延迟决定，再冻结实测，本文不凭空宣布某个Hz已经可用。

长距离全局引导不必每个控制周期重算。把路径进度作为可调变量；只有确需反向才能进入倒车模式。保持每一实际命令可追溯，而非同时运行互相修改状态的多个控制器。

完整后备资格与实际每段必等满整条停车尾是两个不同概念。但**当前冻结实验要求的2,200步尾不删除、不缩短**。若未来要以实测停稳集替代固定等待，必须另立可验证的终端合同和新批次，不能把旧失败追认为通过。

### 4.3 RP-CCR的安全合同必须包括误差与延迟

以下是待实现/证明的目标合同，并非已成立定理。设预测整车集合为B(z)，模型/估计/跟踪误差管束为E_k，原因果障碍外集为O_k。对拟执行前缀及完整后备，至少应验证：

`dist(B(z_k) ⊕ E_k, O_k) >= 0.15 m`，并同时满足自体、合法ctrl/速率、静态体固定、合法模式转换和后备终端条件。

如何由当前raw门0.243534210 m推导到上述集合约束，需逐项核对已有储备；不重复扣同一裕度，也不把新模型误差藏在旧常数里。求解耗时内的车体与障碍运动、测量龄期和控制应用延迟必须进入同一时间轴。

超过截止仍没有新证书，必须从**届时真实/保守包络状态**接续仍有效的旧后备；不能从旧预测根重放已经过时的停车源。实际状态超出后备有效管束时，不能继续声称仍有递归保证，须记录明确失证并触发事前定义的独立停机策略。

### 4.4 安全、任务进展和拓扑选择分开表述

安全是每步必满足的合同；到达是完整任务功能门。中间离目标变远可以是必要绕行，不强迫欧氏目标距离每一步下降。

可研究一个包含路径进度、剩余控制代价、可恢复余量和拓扑类别的进展指标；在规定可行条件下要求有限时域改善，无法改善则切换有限候选类别。该指标及其可行性条件尚待构造，**不能借用稳定性过滤器结论，直接宣布全局必达**。

每个任意中间路径点都不是物理任务目标。当前每gear的0.02 m门保持；未来若改用经认证的走廊/终端集合代替离散点，应明确新语义、独立登记，且保留原实际净空和任务目标，不靠放宽旧门制造胜率。

### 4.5 WE需要的时空修订单独研究

整个周期占据并集要求车永远避开actor可能经过的所有位置，可能封住实际分时可通过的通道。时空版本应使用原因果O(t)，而不是输入仿真真值相位；完整停车和长期终端保持也要在相同时间/运动假设下安全。

从全周期空间合同改成时变合同是实质科学修订，不能偷换原保证。先保留EW当前已过的较保守软件证据，再用WE保存态检验时空连接；不同时变地图、车体、传感和安全门。

## 5. 论文的创新可以放在哪里

建议暂定研究问题：**执行器模式切换和有限计算预算下，如何从原因果观测建立可执行恢复走廊，使名义进展、在线安全认证和失效后备保持一致？**

潜在贡献必须落实到可检验的新机制，例如：

1. 带实际转向/分配器记忆/换挡模式的恢复管束及其组合条件；
2. 将证书龄期、反馈误差、求解截止与旧后备接续一并处理的准入规则；
3. 与进展相容的有限拓扑修复，并明示哪些可行条件下能给出什么进展结论。

这只是候选研究方向。PSF、predictive stability filters、RTD-D/RTD-RAX、T-MPC已覆盖其中若干核心思想。需逐条比较假设、算法和证明，找到真实差异；“加入MPC”“换SLSQP”“接Nav2”“加RL”都不足以单独支撑新颖性或RAS录用。

RL当前不在最新恢复执行链上，训练仍0。不建议此时用大规模并行训练掩盖尚未辨识的车辆响应。未来学习策略可提出名义轨迹或热启动，仍经同一认证器；是否提升必须用同模型、同传感、同算力预算的对照和消融证实。

| C：一个实际EW恢复实例 | B通过且取得新有界物理授权后，只验证原失败态完整续行与停车；检查逐原生净空、实际模型误差、合法ctrl、完整自身重放 | 若实际模型偏差超合同，回到A；若认证拒绝，保存可定位的状态/时间约束，不无界重试 |
| D：同版本完整三路线 | 同科学版本从头主任务及成功后完整重复；NS旧成功只作历史对照 | 不能把新EW组件、旧NS与旧WE前缀拼成三路线通过 |
| E：确认与论文 | 前置全过后冻结24清单；再开展MPPI/PRIEST等公平对照、机制消融、实时统计、实机接口与实验 | 开发样本不混确认分母，不凭单图/单回合宣布全面优势 |

本次先完成研究与上述设计记录，不启动A中的新物理模型；CURRENT_EXPERIMENT仍`next_physical_authorized=false`。不自动三路线/24、通宵或训练。

开发流程随之收敛：一个稳定执行核心、一份状态/证书合同、一张关口表；未变化模块复用已有SHA资格。新版本必须对应一个明确的失败假设和可证伪检查，不再把每个小探针当导航里程碑。仍保留原始失败证据，待远端完整核验后按存储政策清理，不能以精简代码为由抹掉失败。

## 7. 仍不能写进论文的结论

当前不能宣称同版本动态三路线/完整24确认通过、实时闭环、任意遮挡/突入/多actor/任意地图、原更宽每轴0.12运动类覆盖、递归安全或全局必达保证。V1111只支持公开单小actor课程和保存态经验模型下的名义资格。

当前确有进展：原先“完整到达与安全约束不能同时满足”的这个固定EW软件实例，现在已经有全部原门通过的控制源。接下来的关键证据应来自**独立的物理响应和反馈闭环**，而不是继续证明同一模型能重算同一条轨迹。

## 8. 用户要求再审后的决策收敛

用户随后问“上一步的回答可以吗，还是继续改进”。复核结论：上文架构可作为长期方向，但不足以直接决定下一批改动。立即引入新NMPC/acados、重写模型、改时空合同，会同时改变多个因素，且尚无证据证明这些改动都是取得下一次EW实际进展所必需。**短期先保持V1111可复核基线，进行最小的模型—执行判别，再按结果选择唯一改动。** 本节优先于第4节中可能被理解为“立即全面重构”的实施顺序。

必须校正三个判断：

- 停轮调向约4.6°是经验模型的明确机制及未覆盖的验证范围，不是已经测到的物理错误，更不能解释全部历史失败。禁止未经测量就把系数删掉或置零。
- 38.94秒为求解加审计总墙钟，尚未分项测量，不能据此把全部时间归因于在线优化。未来优化结构的选择应依据真实工作分解和控制截止。
- V1111的124条后备从间隔125步的状态起算；这与“每个实际执行接管点均有有效后备”不同。整源全原生几何检查也不能替代所有实际偏差状态的后备验证。

下一轮要区分三种可证伪解释，而非预先指定根因：

| 解释 | 应观察到的证据 | 决策 |
|---|---|---|
| 新调轮/换挡模式的预测误差超过现有合同 | 同初态、同合法关节ctrl下，MuJoCo位姿/速度/转角响应超出事前规定的误差包络；可能集中出现在某一模式 | 只修正该模式模型及误差界，保留可复用模块 |
| 模型预测足够准确，但执行/证书接续不一致 | 物理响应在包络内，却出现ctrl/记忆/模式/时间戳不一致，或当前接管点缺合格后备 | 修正执行与认证事务，先不换规划器 |
| 模型与接口都合格，在线计算仍错过截止 | 分项计时显示真实控制链超出预算，且在超时注入时旧后备不能按合同接续 | 再评估热启动、灵敏度、多重射击/RTI等有针对性的加速 |

最小下一批应先复用已有数据覆盖的响应；对缺少数据的新模式，准备固定的“完整停车→零后驱调轮→重新起步”MuJoCo组件，包含所需的两个调轮方向。状态来源、实际控制、误差包络来源、完整停车/几何/接管门及工作上限在启动前冻结。不得从一个尚未实际抵达的名义中间状态直接初始化并宣称是原路线真实续接；人工构造的组件初态须单独声明。通过后再验证原EW保存失败态的完整闭环恢复及成功条件重复。

新物理批及其窗口仍未启动。本次只更新研究决策，不拟合新模型、不更换算法、不新增预测积分。中长期架构与论文创新待上述判别和同合同对照后再收敛，不能靠新术语代替性能证据。
