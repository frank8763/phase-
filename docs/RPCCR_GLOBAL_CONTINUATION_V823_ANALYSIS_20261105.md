## 结论

最有直接证据的下一步，是给RP-CCR补上“分段恢复参考向完整目标参考升级”的事件触发。保留原Hybrid A*及全部实际控制安全门，先检验这个单一改动，不立即叠加新动作、MPC、训练或更大搜索预算。

第265步得到的只是SAFE_PROGRESS_PREFIX，终点离原目标还有1.929047m。第282步真实新观测恢复目标连通性后，完全原规划器能够生成GLOBAL_GOAL_PATH；原运行却仍沿用265分段路径，因为它局部有效、跟随也在进展，现有触发条件没有要求检查新获得的目标续接机会。车辆后来走到这条分段路径末端附近，再规划时观测已老化，当前估计占据重新变宽。

这是具体的参考更新缺口证据，尚不是该修订实际到达的证明。新的完整几何参考没有经过新控制的完整328原生尾资格，也没有被车辆实际执行。

## 因果解释与边界

原`run_static.py`主要在参考失效、临近末端、明显偏离或停滞时重规划。原282和500的`route_revalidation.jsonl`均显示last_plan=265、current_route_invalid=false、stagnated_without_route_progress=false，reference_path与265相同。其逻辑可以在旧参考还能走时长期不更新，从而错过新观测提供的更好续接。

第265步原引导不连通时，有限搜索仍可接受使启发值下降的局部前缀。局部安全与前缀进展不能代表这个前缀最终能连接原目标。到564/604时旧引导又不连通，搜索采用欧氏距离加20惩罚；日志中约21.96的启发值不是剩余实际距离。两次主回退各16000扩展，上层还有4000优先与前向/双向尝试，不能把16000当总工作量。

因此，目前证据不支持“只要加运行时长就会到达”，也不支持“所有连续控制无解”。它支持先修参考更新的语义和触发。车辆能跟随原分段参考并不等于其正在跟随一条完整到目标的路径。

另有方向适配问题值得单独测试：继承的`forward_curve.py`平滑入口要求世界坐标+x单调、航向绝对值<pi/3，不能将西东表现直接外推到南北/东西。但它没有被证明是本次续接失败的充分原因，不与首个触发修订打包救回。

## 下一候选的最小设计（未实现、未物理验证）

1. 每条参考显式保存GLOBAL_GOAL_PATH或SAFE_PROGRESS_PREFIX、目标剩余距离及生成它的原因果观测版本。局部前缀保持可用，但不当完整全局路线。
2. 跟随前缀时，新观测使当前地图重新出现到原目标的有限引导，就触发原规划链；继承原最小12公开步重规划间隔，避免每帧完整搜索。只有真正得到完整目标路径才升级参考，失败则保留原可用参考/安全尾，不伪装为成功重规划。
3. 新参考只提供目标方向。每个实际命令仍必须通过原完整8+320控制尾、因果不确定域和全部执行安全门；原合法速率、停车换向、329执行/657规划覆盖不变。几何连通不能绕过这些门。
4. 若这个单一改动仍失败，先归因是新参考对应控制无联合合格尾，还是执行中观测再次丢失。届时再独立研究观察保持或有限不同绕行类别，不在本轮同时修改控制评分、运动类和搜索预算。
