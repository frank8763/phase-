## 原记录诊断与可确认的原因

零模型脚本`experiments/v1297_turn_evidence_closure/diagnose.py`读取原实际轨迹/命令而非重新驾驶，确定性复核：

1. 第1–500原生平均请求角速度.026247570rad/s、实际.015917095rad/s；请求累计转角.131237848rad、实际积分.079585477rad，初段存在实际响应滞后。
2. 第1001–1480原生平均请求角速度已降至.001413729rad/s；末四个请求角速度约-.000245、-.000386、-.000537、0，说明临近目标时上层已经削弱/略反向调转，并非仍持续要求本车达到.3rad。
3. 最后实际指向组件终点的方位角为.167665569rad，实际车身航向为.168341373rad，两者仅差.000675805rad。这个行为与追逐终点位置而非最终路径切线一致。
4. 原上游goal checker yaw tolerance为pi，RPP rotate_to_heading=False。其原生action通过不代表新增独立切线航向门通过。完整ctrl分配与自身重放精确，未发现另一个控制器抢写ctrl的证据；这也不意味着物理车身能无误差实现名义v,w。

这些数据确认“位置型末段处理+实际转向响应滞后”同时存在；一次组件没有因果对照，不能断言调整一个参数就必定解决。0.13166对0.12只是超门约0.01166rad，仍保留失败、不事后放宽。
