# V1070：冻结SAC候选层接入

用户明确要求将强化学习加入当前RP-CCR。当前实际栈使用已知静态地图，未知小actor由真实测距发现；近几版加载旧SAC但实际导航不调用它决策，BC是监督学习。

本模块已实现并核验两个原始SAC策略：Phase6的107维基础策略 + Phase20的186维/二维残差策略，融合系数保持0.18。原权重不改，无训练更新。精确观测分块不接受缺失、补零、陈旧或真值字段；不能把32束扫描伪装成186维观测。

integration.ShieldedSAC是真正调用策略并通过原Python完整2200停车安全门的候选接口；propose_goal_profile进一步只允许保留完整目标证书的学习前缀，有限停车候选绝不当到达。runtime_hook是下一已资格控制owner的接入点；它不产生第二个控制owner、不写ctrl/qpos、不积分。

当前软件资格：257样本/策略，推理与SB3最大误差分别1.885e-6和1.237e-6，七负例拒绝；在实际保存车状态 + 明确合成的观测块上，1学习候选完整尾安全门接受，实际执行0。这不是实际传感器/整路成功。

仍缺：现导航记录只有原32束测距等，必须接入并资格验证旧策略所需的36束基础测距/24维真实深度、两组融合深度/目标等观测。不能给缺失深度补零/常数而声称是原策略。此次没有建立/启动该额外传感后端，也没有新车辆窗口。原型函数存在不等于已在车上运行；当前physical_ready=false。额外传感会改变观测合同，公平对照必须使用同输入。未知地图能力没有因此成立。
